# Deploy the CosmicSeeker Anchor program

End-to-end walkthrough for getting the `program/` workspace onto devnet or
mainnet. The wrapper at `program/scripts/deploy.ts` validates everything
that's safe to check before the upload starts, then shells out to
`anchor deploy`. A separate `program/scripts/initialize.ts` calls the
one-shot `initialize` instruction afterwards.

> **You need a funded Solana keypair on disk.** The script does *not* mint,
> airdrop, or transfer SOL for you. See step 2 below.

## 0 · Prerequisites (one-time, on your laptop)

```bash
sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"   # Solana CLI
cargo install --git https://github.com/coral-xyz/anchor avm --force
avm install 0.30.1 && avm use 0.30.1                            # Anchor CLI
```

Verify:

```bash
solana --version    # solana-cli 1.18+
anchor --version    # anchor-cli 0.30.1
```

## 1 · Mint a real program id

From `program/`:

```bash
cd program
anchor build                # creates target/deploy/cosmic_seeker-keypair.json
anchor keys list            # prints the on-chain program id
anchor keys sync            # writes it into Anchor.toml + declare_id!()
```

`anchor keys sync` rewrites both `Anchor.toml` and the `declare_id!()` macro
inside `programs/cosmic-seeker/src/lib.rs`. After this step the deploy
script's "still using the placeholder" guard will pass.

## 2 · Fund the deployer keypair

```bash
solana-keygen new -o ~/.config/solana/id.json     # if you don't already have one
solana address                                    # prints the pubkey
solana airdrop 2 -u devnet                        # devnet only; ignored on mainnet
solana balance -u devnet                          # expect ≥ 4 SOL
```

For mainnet, bridge SOL into the printed address with whatever onramp you
prefer. The wrapper bails out if balance < 4 SOL.

## 3 · Deploy

```bash
npm install        # in program/, one time
npm run deploy:devnet
# or:
npm run deploy -- --cluster devnet
```

The wrapper:

1. Confirms `declare_id!()` and `Anchor.toml [programs.devnet]` agree
   (refuses to deploy with the placeholder).
2. Verifies the deployer balance (≥ 4 SOL).
3. Refuses mainnet deploys unless `COSMIC_CONFIRM_MAINNET=yes` is set.
4. Runs `anchor build` (skip with `--skip-build`).
5. Runs `anchor deploy --provider.cluster devnet --program-keypair …`.
6. Prints the program id + balance delta on success.

## 4 · One-shot `initialize`

Pick the SKR mint + treasury pubkeys you want baked into the `Config` PDA,
then:

```bash
# pubkey that matches backend/.env::SIGNER_KEYPAIR_BASE58
SIGNER_PUBKEY=<redacted-leaked-pubkey>

# SKR SPL mint address (create with `spl-token create-token --decimals 6` if you don't have one)
SKR_MINT=<your-spl-token-mint>

# Wallet (or PDA) that should receive the treasury-half of every buy_item
TREASURY=<your-treasury-wallet>

npm run initialize -- \
  --cluster devnet \
  --signer-pubkey "$SIGNER_PUBKEY" \
  --skr-mint     "$SKR_MINT" \
  --treasury     "$TREASURY"
```

The script:

- Loads `target/idl/cosmic_seeker.json` (generated by `anchor build`).
- Derives the `Config` PDA (seed `b"config"`).
- **Refuses if the PDA already exists** — `initialize` is one-shot. To
  rotate any of these fields you must either add an admin instruction or
  redeploy under a new program id.
- Calls `initialize(signer_pubkey)` with the three accounts.
- Prints the tx signature + a `solana confirm` one-liner to verify.

## 5 · Wire the program id into the frontend

After deploy, set the env var the frontend reads (planned for the next
loop iteration — `src/web3/solana.ts`):

```env
VITE_COSMIC_PROGRAM_ID=<the program id from step 3>
```

Then rebuild the APK as in `docs/DEPLOY-COSMIC-SOULVIEW.md` so it picks up
the new program id.

## 6 · Upgrade

`anchor deploy` redeploys atomically — no downtime. The `Config` PDA stays
intact (Anchor `init` constraint), so nonces and treasury authority survive
upgrades. To redeploy:

```bash
npm run deploy:devnet -- --skip-build      # if you already ran `anchor build`
```

## Troubleshooting

| Symptom                                                | Cause / fix                                                                              |
|--------------------------------------------------------|------------------------------------------------------------------------------------------|
| `declare_id!() is still the placeholder`               | Run `anchor keys list && anchor keys sync` first.                                        |
| `deployer has X SOL — need at least 4`                 | Airdrop on devnet, bridge on mainnet, then retry.                                        |
| `program id mismatch …`                                | `Anchor.toml [programs.<cluster>]` and `declare_id!()` disagree. Re-run `anchor keys sync`. |
| `Config PDA already initialized for this program`      | `initialize` already ran. The PDA can't be re-initialised — redeploy under a new id.     |
| `ed25519 verification failed` in claim tx              | Backend signer pubkey ≠ `Config.signer_pubkey`. Re-run `initialize` (after redeploy).    |
| `program/target/idl/cosmic_seeker.json` not found      | Run `anchor build` first; the IDL JSON is a build artefact.                              |
